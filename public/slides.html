01 The hook the whole talk in one slide

A chatbot replies. An agent decides.

Chatbot

you   → remind me to call the dentist
        tomorrow at 9
bot   → Sure, I'll remind you!

Tomorrow at nine, nothing happens. It has no clock, no database, and no way to send you a message you did not ask for. It produced text that sounds like an action.

Agent

you   → remind me to call the dentist
        tomorrow at 9
model → CreateReminder { remind_at: "2026-08-31 09:00" }
app   → validate, then insert into reminders …
model → Done, I'll nudge you Monday at 09:00.
─── the next morning, 09:00 ───
bot   → ⏰ Call the dentist

The model chose the tool and worked out the date. Your code checked it, stored it, and a scheduled command sent the message a day later — with no one in the chat.

02 The pieces the three parts

What you are actually stitching together

the skeleton

Laravel

A route, a controller, a job, an Eloquent model. Nothing here is AI-specific, and that is the point: the interesting part is ordinary web plumbing.

the mouth and ears

Telegram Bot API

A JSON HTTP API. Updates arrive by webhook or long polling; replies go out with sendMessage. Reach for a package like telegram-bot-sdk, or write the five endpoints you need yourself.

the brain

laravel/ai

Laravel's first-party AI SDK. Agents, tools, conversation memory, structured output, streaming and provider failover, behind one API across a dozen providers.

This repo takes the hand-rolled option: app/Services/Telegram.php is 126 lines of Http::post() covering sendMessage, sendChatAction, getUpdates, setWebhook and deleteWebhook. That is the entire surface a bot needs.

03 What “agentic” means the whole contract

Anatomy of an agent

01instructions() — who it is and how to behave
02tools() — what it is allowed to do
03RemembersConversations — what it recalls
04schema() — optional: answer as typed JSON, not prose. This bot doesn't need it; its tools carry the schemas

Everything else is a trait. Promptable gives you prompt(), stream() and queue(); the interfaces are how the SDK knows which of them apply.

Instructions are built per call, so anything the model cannot know — the clock, most of all — goes in here rather than in the prompt.

app/Ai/Agents/TelegramAssistant.phpclass TelegramAssistant implements Agent, Conversational, HasTools
{
    use Promptable, RemembersConversations;
 
    public function instructions(): Stringable|string
    {
        $now = now();
 
        return <<<INSTRUCTIONS
        You are a helpful assistant living inside a Telegram chat.
        Keep replies short, the way a person texts.
 
        You set reminders, list what is coming up, and cancel the
        ones they change their mind about.
 
        It is {$now->format('l j F Y, H:i')}. Work reminder times out
        against that clock and pass them to CreateReminder as
        YYYY-MM-DD HH:MM.
        INSTRUCTIONS;
    }
    public function tools(): iterable
    {
        return [new CreateReminder($this->chat), new ListReminders($this->chat), …];
    }
}
03 What “agentic” means the interesting part

A tool is a PHP class the model is allowed to call

Three methods. The SDK turns them into a function definition the provider understands.

namethe class basename, verbatim: CreateReminder
descdescription() — the only hint the model gets about when to use it
argsschema() — a typed JSON schema it must fill in
runhandle() — your code, your database, your rules

The model never touches your database. It asks for a tool by name with arguments; the SDK validates them, calls handle(), and feeds the returned string back into the conversation.

what the provider is sent{
  "name": "CreateReminder",
  "description": "Set a reminder to be delivered to the user
    later. Work the date out from the current time in your
    instructions and pass it as YYYY-MM-DD HH:MM.",
  "parameters": {
    "type": "object",
    "properties": { "body": { … }, "remind_at": { … } },
    "required": ["body", "remind_at"]
  }
}
turn 1  model  → CreateReminder { remind_at: "2026-08-31 09:00" }
turn 1  app    → "Reminder #1 set for Mon 31 Aug 2026, 09:00."
turn 2  model  → "Done, I'll nudge you Monday at 09:00."

One user message, two round trips to the provider. MaxSteps caps how many times that loop may run.

03 What “agentic” means trust, then verify

The model has no clock. Give it one, then check its work.

“Tomorrow at 9” is arithmetic against a date the model does not have. Hand it the date, name the format you want back, and validate what arrives.

nowthe current moment goes into the instructions on every call
shapethe tool's schema names the exact format it wants
bailstop at the first broken rule, before anything is written
askthe failure message is the next thing the model reads

This is the whole trick: a validation message is not a log line, it is a prompt. Write it as an instruction to the model and a bad argument turns into a better question for the user.

app/Ai/Tools/CreateReminder.php$validator = Validator::make($request->all(), [
    'body' => ['required', 'string', 'max:255'],
    'remind_at' => ['bail', 'required',
        'date_format:'.self::FORMATS, 'after:now'],
], [
    'remind_at.date_format' => 'That is not a date I can read. Ask'
        .' the user for a specific day and time, then pass it as'
        .' YYYY-MM-DD HH:MM.',
]);
 
if ($validator->fails()) {
    return $validator->errors()->first();
}
model → CreateReminder { remind_at: "sometime next week" }
app   → That is not a date I can read. Ask the
        user for a specific day and time …
model → Happy to set that — which day next week,
        and what time?
03 What “agentic” means persistence

Why it remembers you between messages

HTTP forgets everything. A conversation cannot.

traitRemembersConversations persists every message for you
rowone conversation_id stored on the chat
whoas: and forParticipant() scope it to that chat
wipe/forget nulls the column — instant fresh start

Two migrations from the SDK do the storing: agent_conversations and agent_conversation_messages. Reminders live in your own table instead, because a reminder has to outlive the conversation that set it.

app/Services/TelegramBot.phpif ($text === '/forget') {
    $chat->update(['conversation_id' => null]);
 
    return 'Done, I have forgotten our conversation.';
}
 
$agent = new TelegramAssistant($chat);
 
$response = ($chat->conversation_id
    ? $agent->continue($chat->conversation_id, as: $chat)
    : $agent->forParticipant($chat))->prompt($text);
 
$chat->update(['conversation_id' => $response->conversationId]);
 
return $response->text;

04 The code step 1 of 4  ·  in

Step 1 — Telegram posts to a route

One public POST route. Verify, hand off, answer with nothing.

authTelegram signs every request with a header you chose
fastthe job means the model call is not in this request
204an empty body is a complete, correct reply here

This route is on the public internet with no session and no CSRF token. The secret header is the whole door.

routes/web.phpRoute::post('/telegram/webhook', TelegramWebhookController::class)
    ->name('telegram.webhook');
 
// app/Http/Controllers/TelegramWebhookController.php
public function __invoke(Request $request): Response
{
    $secret = (string) config('services.telegram.webhook_secret');
 
    abort_if(
        $secret !== '' && ! hash_equals($secret, (string) $request->header(
            'X-Telegram-Bot-Api-Secret-Token'
        )),
        403,
    );
 
    HandleTelegramUpdate::dispatch($request->all());
 
    return response()->noContent();
}
04 The code step 2 of 4  ·  hand off

Step 2 — the update becomes a prompt

The only class that knows about both Telegram and the agent. Everything else stays ignorant of the other side.

skipno text, no work — stickers and joins arrive here too
whofirstOrCreate on the Telegram chat id
feelfire the typing indicator before the slow part

Commands like /start and /forget are answered from PHP, with no model call at all. Not every message deserves a token bill.

app/Services/TelegramBot.phppublic function handle(array $update): void
{
    $message = $update['message'] ?? null;
    $text = trim((string) ($message['text'] ?? ''));
 
    if ($text === '') {
        return;
    }
 
    $chat = $this->chatFor($message);
 
    $this->telegram->sendTyping($chat->telegram_id);
    $this->telegram->sendMessage($chat->telegram_id, $this->reply($chat, $text));
}
 
private function chatFor(array $message): TelegramChat
{
    return TelegramChat::firstOrCreate(
        ['telegram_id' => $message['chat']['id']],
        ['name' => $message['chat']['first_name'] ?? null],
    );
}
04 The code step 3 of 4  ·  act

Step 3 — the tool, in full

48 lines. Three methods, and one of them is a sentence.

scopethe chat is injected, so a tool can only touch that chat's rows
args$request->integer('id') — shaped by the schema you declared
backreturn a string; the model reads it and writes the reply

Scoping in the constructor rather than in a tool argument matters. whereKey($id) runs inside $this->chat->reminders(), so the model cannot reach another chat's rows — it was never given a way to name one.

app/Ai/Tools/CancelReminder.phpclass CancelReminder implements Tool
{
    public function __construct(private readonly TelegramChat $chat) {}

    public function description(): Stringable|string
    {
        return 'Cancel one of the user\'s reminders by its id. Use'
            .' ListReminders first if you do not know the id.';
    }
    public function handle(Request $request): Stringable|string
    {
        $id = $request->integer('id');
        $cancelled = $this->chat->reminders()->pending()->whereKey($id)->delete();
 
        return $cancelled > 0
            ? "Cancelled reminder #{$id}."
            : "No reminder #{$id} is waiting to be sent.";
    }
    public function schema(JsonSchema $schema): array
    {
        return [
            'id' => $schema->integer()
                ->description('The id of the reminder to cancel.')
                ->required(),
        ];
    }
}
04 The code step 4 of 4  ·  out

Step 4 — send it back

The Bot API is a POST with a JSON body. That is the whole client.

okTelegram answers 200 with {"ok": false} — check the body, not the status
timea long poll holds the connection open, so timeouts must be generous
hidethe token is in the URL, so scrub it before anything is logged
app/Services/Telegram.phpprivate function call(string $method, array $payload = []): mixed
{
    try {
        $response = Http::asJson()
            ->connectTimeout(10)
            ->timeout(60)
            ->post("https://api.telegram.org/bot{$this->token}/{$method}", $payload);
    } catch (ConnectionException $e) {
        throw new RuntimeException("Telegram [{$method}] unreachable: "
            .$this->scrub($e->getMessage()), previous: $e);
    }
 
    if (! $response->successful() || $response->json('ok') !== true) {
        throw new RuntimeException("Telegram [{$method}] failed: "
            .$this->scrub($response->body()));
    }
 
    return $response->json('result');
}
04 The code the whole path

“Remind me to call the dentist tomorrow at 9”

Nine hops, two of them slow, none of them inside the HTTP request Telegram is waiting on.

Steps 5 and 7 are the only ones that cost money or wall-clock time. They run in a worker, where waiting is free — and where a crash is a failed job you can see and replay, not a dropped webhook.

04 The code the other direction

Nobody is in the chat when a reminder goes out

Every other message in this app answers an update. This one answers a clock.

cronone scheduled command, every minute
dueone indexed query: not delivered, and the time has come
retrya refused send stays undelivered, so the next minute tries again
freeno model call at all — the words were written when the reminder was set

The moment your bot can message people unprompted it stops being a chat feature and starts being infrastructure: it needs a schedule, a retry story, and somewhere to see what went out.

routes/console.phpSchedule::command(DeliverReminders::class)->everyMinute()->withoutOverlapping();
 
// app/Console/Commands/DeliverReminders.php
public function handle(Telegram $telegram): int
{
    $reminders = Reminder::due()->with('telegramChat')->get();
 
    foreach ($reminders as $reminder) {
        try {
            $telegram->sendMessage($reminder->telegramChat->telegram_id, "⏰ {$reminder->body}");
        } catch (Throwable $e) {
            // Leave it undelivered so the next run tries again, rather
            // than losing a reminder to one bad minute of network.
            report($e);
 
            continue;
        }
 
        $reminder->update(['delivered_at' => now()]);
    }
 
    return self::SUCCESS;
}

05 What bit me gotcha 1  ·  timeouts

Never make Telegram wait for a model

Telegram expects a prompt response to a webhook delivery, and redelivers an update it did not get one for.

buga slow generation reads as a failure, so the update comes back
worsethe second delivery answers too — the user gets two replies
fixack immediately, generate in a worker

The SDK's own $agent->queue($text)->then(…) backgrounds the model call. I queue the whole handler instead, because the reply still has to be sent — and that is one more network hop that can hang.

app/Jobs/HandleTelegramUpdate.phpclass HandleTelegramUpdate implements ShouldQueue
{
    use Queueable;
 
    /**
     * A retry would send the user a second reply, so a failed
     * update is dropped and reported instead.
     */
    public int $tries = 1;
 
    public function __construct(private readonly array $update) {}
 
    public function handle(TelegramBot $bot): void
    {
        $bot->handle($this->update);
    }
}
05 What bit me gotcha 2  ·  failover

One provider is a single point of failure

Free tiers get rate limited. Popular models get overloaded. Credit runs out on a Friday.

yesRateLimitedException
yesProviderOverloadedException
yesInsufficientCreditsException
nobad requests and validation errors — those are your bug

Only a FailoverableException moves to the next provider, which is what you want: a malformed tool schema should fail loudly on the first try, not four times against four vendors.

app/Ai/Agents/TelegramAssistant.php/** @return list<string> */
public function provider(): array
{
    return [config('ai.default'), ...config('ai.failover')];
}
.envAI_PROVIDER=gemini
AI_FAILOVER_PROVIDERS=openai,anthropic
or per prompt, no config at all$agent->prompt($text, provider: [Lab::Gemini, Lab::OpenAI]);

Three providers, one deploy, no application code aware of any of them.

05 What bit me gotcha 3  ·  the last mile

Telegram will refuse a perfectly good reply

The model writes prose. The Bot API has opinions about prose.

4096hard cap per message — split before sending, not after failing
mdan unbalanced * or a bare _ makes the whole call fail
tellsay “keep it short” in the instructions and most of this stops

Losing the bold is fine. Losing the reply is not. That single catch was the difference between a bot that looks broken and one that looks plain.

app/Services/Telegram.phppublic function sendMessage(int $chatId, string $text): void
{
    foreach (mb_str_split($text, 4000) as $chunk) {
        $this->sendChunk($chatId, $chunk);
    }
}
 
private function sendChunk(int $chatId, string $text): void
{
    try {
        $this->call('sendMessage', [
            'chat_id' => $chatId,
            'text' => $text,
            'parse_mode' => 'Markdown',
        ]);
    } catch (RuntimeException) {
        // A model can emit Markdown that Telegram refuses to parse,
        // and dropping the reply is worse than losing the formatting.
        $this->call('sendMessage', ['chat_id' => $chatId, 'text' => $text]);
    }
}
05 What bit me gotcha 4  ·  the rest

Four smaller ones, quickly

rate limits

Telegram counts too

Telegram's guidance is roughly one message per second per chat and about thirty per second overall. Splitting a long reply into chunks can walk straight into that — throttle the sends, not just the prompts.

secrets

The token is in the URL

Every Bot API call puts the token in the path, so any logged error message leaks it. One scrub() before anything reaches a log or a screen, and a bot token stops turning up in stack traces.

networks

Conference wi-fi drops

telegram:poll holds a 25-second connection open. Left plain, one dropped packet ends the demo; wrapped in a catch-warn-continue loop, it just reconnects.

tests

Fake the model

TelegramAssistant::fake([…]) and Http::fake() cover the whole pipeline, tools included. 26 tests, no network, no tokens, 0.4 seconds.

06 Wrap up the mental model

Keep these three apart and it stays simple

the interface

Telegram

Delivers text, sends text. It knows nothing about models, and should stay that way.

the orchestration

Laravel

Routes, jobs, database, tests. Decides what runs, when, as whom, and what happens when it fails.

the brain

laravel/ai

Picks the words and picks the tools. It only ever gets to ask for an action — your class performs it.

The agent is the only new idea in the whole talk, and it is a class with four methods. Everything that makes it feel alive — memory, tools, failover, the scheduled nudge at nine in the morning — is ordinary Laravel around it.
